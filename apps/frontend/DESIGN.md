# Orchard UI 3.0

Everything a screen needs is in `src/lib/components/ui` (primitives) and
`src/lib/components/patterns` (recipes). The living catalogue is `/dev/ui` (run
`pnpm dev`, open `localhost:3000/dev/ui`). If a screen needs something that is not in the
catalogue, add it to the kit and the catalogue first; never hand-roll it in a route.

## Constitution

1. One way to do each thing. Every need maps to exactly one component.
2. Space comes from the 4px grid: Tailwind `0.5 1 2 3 4 6 8 12 16` only. A container's
   padding is at least 1.5x the gap between its children. Gaps between groups are about
   2x the gaps inside a group.
3. Hierarchy comes from weight and tone, not size. Three weights (450, 550, 650), three
   text tones (`fg`, `muted`, `faint`).
4. Colour means something. Neutral surfaces with the theme tint, one accent, status
   colours only for status. Status is never colour alone.
5. One representation per entity. A deployment, database or job always renders through
   `EntityRow`. Everything else is progressive disclosure.
6. Motion is physics, and only transform and opacity move. Named springs only.
7. Glass is for floating chrome only (menus, popovers, toasts, command menu).
8. Spend novelty on deploy moments and project identity (aura, toasts). Everything
   else is quiet on purpose.
9. Every word earns its place. Copy that does not change what someone does or knows
   is cut, not toned down.

## Copy that earns its place

Before adding a subtitle, hint or note, ask what someone would do differently after
reading it. If the answer is nothing, delete it.

- **Cut reassurance.** "Takes about a minute. Everything stays editable afterwards."
  The progress UI shows how long it takes; editability is assumed.
- **Cut restated titles.** A "Configure" card does not need "Applied when it deploys".
  A "What gets created" list does not need "Everything lands in this project".
- **Keep consequences.** "Leave them empty and Orchard generates strong values" changes
  behaviour, so it stays. So does "Org defaults if you skip this".
- **Keep the specific.** A hint that names a real value (`blog_site_name`,
  "17 is the recommended default") beats one that describes the field.
- One line, sentence case, no trailing marketing. If a hint needs two sentences, the
  field probably needs a better label or a default.

### Correlation sentences

Findings, deploy verdicts and anything else that explains what happened to an app are
written by the server (`observability/correlate.ts`, `observability/verdict.ts`) and follow
the same rules everywhere, including over MCP:

- **Observation first, then the cause, with numbers and times.** "Errors went from 0.2% to
  4.1% at 14:02, two minutes after v7 went live." "Memory has climbed about 40 MB an hour
  since 09:10 and reaches its limit around 17:30."
- **Never hedge.** No "It appears", "may indicate", "seems", "potentially", "likely" or "AI".
  No exclamation marks, no em dashes.
- **Weak evidence means no sentence.** No finding beats a vague one.
- **Name what the user named:** the version, the domain, the env var key. Never a pod hash
  unless pods differ.
- **Past tense for events, present tense for current state.**
- Each sentence links to its moment (`?at=` permalink).

## Patterns to avoid

These make a screen read as generic. The rule for each:

- **Cards inside cards.** Nest only when elevation means something: a sunken tray holding
  raised cards, never a bordered card inside a bordered card.
- **The same chrome on every repeated item.** Show status in words ("1 failing"), and put
  per-item actions on hover. One primary action per page.
- **Decorative colour.** Red only means broken, amber only in progress, green only healthy.
  Identity colours (app icons) never use red.
- **One radius everywhere.** Containers 18, cards 14, controls 10, inner tiles 8.
- **Fake people and fake art.** Use the real org logo, avatars and project icons; fall back
  to a glyph, never a lone letter.
- **Generic copy.** Say what is true right now ("Everything is running except 3 apps").

## Why it looks expensive (do all of these)

- **Optical alignment.** Icons centre on the text's cap height, not its line box. Text
  that sits next to an icon, or inside a pill, uses `text-box: trim-both cap alphabetic`
  so padding is measured from the ink. Verify with `/dev/ui` and a measured audit: icon
  centre vs cap centre, delta 0.
- **Continuous corners, not circles.** Every rounded rectangle writes
  `border-radius: calc(R * var(--corner-scale)); corner-shape: var(--corner);` where R is
  the nominal radius (`--radius-control` 10px, `--radius-card` 14px,
  `--radius-panel` 18px). `--corner` is `superellipse(1.4)` and `--corner-scale` is 1.25,
  fitted by pixel diff against Figma's 60% corner smoothing; plain
  `squircle` at the same radius reads boxy. Browsers without `corner-shape` fall back to
  round corners at scale 1. Circles only for status dots, radios and the switch; capsules
  only for the toast.
- **Dense, not big.** It is a developer tool: 32px controls, 36px nav rows, 14px body.
- **Concentric corners.** Inner radius = outer radius minus inset. A circle inside a
  capsule sits at an inset equal to `(height - circle) / 2`. Never nest equal radii.
- **Hairlines, not borders.** 0.5px to 1px rings in `--border-default`, drawn once.
  Elevation is a ring plus a soft layered shadow, never a hard 1px grey box.
- **Light from above.** Raised controls get a faint top inner highlight
  (`inset 0 1px 0 rgb(255 255 255 / 0.12)`) and a small drop shadow. Pressed controls
  scale to 0.96.
- **Restraint.** One primary button per view. Colour only where it means something.
  Generous whitespace. Muted secondary text.
- **Numbers are tabular** (`font-variant-numeric: tabular-nums`) everywhere they change.
- **Every state is designed:** rest, hover, pressed, focus-visible, disabled, loading,
  empty, error. Focus is a soft 3px accent ring, never the browser outline.
- **Motion is interruptible and staged.** Shape first, content after. Closes settle
  flat (no bounce). Nothing teleports: if a thing leaves a list, the gap closes with it.

## Tokens (`src/lib/design/`)

- `scales.css` is generated (`pnpm gen:design`) from the theme engine: `--neutral-*`,
  `--accent-*`, `--red-*`, `--amber-*`, `--green-*`, `--blue-*`, steps 1 to 10, plus
  `-contrast` (text on step 7). The theme store repaints them live.
- The neutral scale is built from the composed palette (wheel plus pinned colours), the
  way the earlier UI mapped its tokens straight onto the engine: `--neutral-app` is the
  Background, `--neutral-surface` the Card, `--neutral-10` the Text, `--neutral-9` Muted
  text, `--neutral-border` the Border and `--neutral-chrome` the Sidebar (opaque when
  pinned). Every other step is derived from them and takes its tint from the
  background's own chroma, so a pinned near-black paints exactly and its ladder stays
  grey. The contrast guarantee only moves derived colours; a pinned value is never
  refitted. A pinned accent is `--accent-7` exactly and a pinned status colour is its
  step 9.
- Step meanings: 1 component bg, 2 hover bg, 3 active bg, 4 border, 5 hover border,
  6 active border, 7 solid fill, 8 solid hover, 9 secondary text, 10 primary text.
- Roles (`tokens.css`): `--bg-app` (tinted frame), `--bg-sheet` (content sheet),
  `--bg-surface`, `--bg-raised`, `--bg-sunken`, `--bg-hover`, `--bg-active`,
  `--text-default|muted|faint|link`, `--border-default|strong`, `--accent`,
  `--status-{kind}` (text), `-solid`, `-bg`, `-border`, `--shadow-raised|floating|overlay`,
  `--material-glass-*`, `--radius-control|card|panel`, `--weight-*`, `--z-*`,
  `--page-narrow|default|wide`.
- Tailwind utilities on top: `text-fg/muted/faint`, `bg-app/sheet/surface/raised/sunken/
hover/active`, `border-edge`, `text-accent`, `bg-accent-soft`, `text-success` (and
  `-soft` backgrounds), type roles `text-display|title-1|title-2|title-3|headline|body|
callout|caption|micro`, `rounded-control|card|panel`.
- Fonts: Plus Jakarta Sans (UI), JetBrains Mono (code, logs, IDs).

## Bold budget

Semibold is spent, not sprinkled. A screen gets one or two semibold things: the page title, and anything that is genuinely wrong (a failing count, a crashed status). Everything else is regular or medium.

- Widget and section titles: medium.
- Names in lists, rows and cards: regular or medium, never semibold.
- Status labels: regular when healthy, semibold only for failures.
- Owners, counts and metadata: regular, coloured or muted instead of weighted.

If a row looks flat without bold, fix it with size, tone or spacing first.

One exception: the brand hero in `AuthShell` (sign-in) speaks like orchard.my, a lowercase
medium headline with one italic word at `--weight-display` (800). That weight exists for
that headline and nowhere else.

## Concentric corners

A surface nested inside another, close to its corner, uses **inner radius = outer radius − the gap between them**, never its own number. Subtract first, then scale: `calc((var(--outer-r) - var(--gap)) * var(--corner-scale))`, with `corner-shape: var(--corner)`. Floor at `--radius-floor` (0.25rem) when the gap is larger than the radius.

- Containers publish their radius and padding as variables (`--widget-r`/`--widget-pad`, `--project-r`/`--tray-pad`, the sidebar's `--nav-radius`, the palette's `--R`/`--inner`) and children derive from them.
- When the padding is big, grow the outer radius from the inner one instead (`--project-r: calc(var(--card-r) + var(--tray-pad))`), so cards keep their shape.
- App icons, avatars and status dots keep their own shape. The rule is for backgrounds: rows, cards, hover fills, thumbs, keycaps, nested panels.

## Highlights never touch

Any list where one row can be selected while another is hovered (sidebar, settings rail, segmented lists) keeps at least `0.25rem` between rows. Two filled backgrounds touching read as one blob, and the hover looks like it is pushing into the selected row.

## Alignment grid

Lay a component out on an explicit grid before styling it, and check it with a reticule (measured offsets, not by eye):

- One padding value all round inside a card (12px for toasts and compact cards).
- A card title sits 12px above its content (`--widget-title-gap`, `--section-title-gap`), always less than the card's padding. A header control (segmented control, stepper, capsule button) sits concentric in the corner and keeps that same 12px below its own bottom edge: content starts under the control, never tucked up beside it. Giving the overhang back below put alerts, pod rows and paragraphs a few pixels under a capsule and read as a collision every time.
- A list or disclosure group directly under a card title starts with a rule, so the title and the first row never read as one block.
- A shared text column: every line of text in a block starts at the same x (toast: icon at 12, text at 44).
- Read top to bottom: title first, detail under it, even when the surface grows upward from a bottom anchor.
- Size to content: a one-line note gets a one-line card, not a fixed minimum.
- Columns of status in a list share a fixed-width, left-aligned column so dots and labels line up.

## Status dots (one language)

Every status indicator is `StatusDot`. Nothing else draws a coloured status circle.

- **The nucleus never changes.** The core is 8px everywhere (lists, badges, headers, pods); only the ring around it varies, like an atom. The ring draws outside the dot's box, so a dot starting or finishing work never moves the layout.
- **Colour is the main status:** green healthy, amber in progress, red broken, blue queued, grey stopped, and violet (`tone="deploy"`, `--status-deploy-*`) for a new version rolling out.
- **Full ring** (`meta.pulse`): work with no known steps. One arc orbits the core.
- **Speedometer** (`steps`): work with known steps. A 270° gauge split into one segment per step: done light, active in the main colour and breathing, failed red, pending faint. Switching from the full ring unrolls the segments into place.
- **Landing:** when the work ends the ring shrinks and fades while the core pops once into its final colour.
- **Hero gauge** (`orbit`): where one piece of work is the subject of a whole surface (the build sheet), the speedometer gets a larger ring through `orbit` (px). The core stays 8px; only the ring grows.
- `StatusBadge` passes `tone` and `steps` through, so a header chip and a pod share the exact same dot.

## App, deploy and build are three different things

`packages/health` (`computeHealth`, imported as `$health`) is the only place that decides what is wrong, from what is true right now. It never keeps history: a pod that crashed and recovered raises nothing.

- **Build:** did the image get made. A failed build changes nothing that is running.
- **Deploy:** is the new version (the newest ReplicaSet, `rollout.currentRevision`) coming up. A new version that crashes, can't pull, misses a secret, has no room or never gets ready is a deploy problem, and the app keeps serving the previous version.
- **App:** is anything serving traffic. Down only when no pod is ready and none is still starting.

Pods carry `revision` (`pod-template-hash`) and the detail returns `rollout` (revisions with numbers, current, previous, state). A rollout is in progress only while Kubernetes says so (`Progressing` is not `NewReplicaSetAvailable`, or two ReplicaSets have pods), so a crash after a finished deploy is an app problem, not a deploy one. During a deploy pods are tagged "v6 new", "v1", or "v4 replaced" when a second deploy superseded the first. A replaced pod never alerts.

### Only real problems, and only while they are happening

Normal Kubernetes behaviour never alerts: a pod starting, pulling, waiting for a node, a drain, a single out-of-memory kill it recovered from. Each signal waits as long as Kubernetes itself usually needs before it is worth a person's attention, the same idea as the `for:` windows in [kubernetes-mixin](https://github.com/kubernetes-monitoring/kubernetes-mixin) and the 15s schedule window in [kstatus](https://github.com/kubernetes-sigs/cli-utils/tree/master/pkg/kstatus). The thresholds live in `PATIENCE` in `health.ts`.

| Signal                                                             | Alerts after                               | Why                                                                            |
| ------------------------------------------------------------------ | ------------------------------------------ | ------------------------------------------------------------------------------ |
| `CrashLoopBackOff`                                                 | at once                                    | Kubernetes already waited through a crash and a restart                        |
| restarts ≥ 2 with the last one under 10 minutes ago                | at once                                    | flapping between running and back-off                                          |
| `CreateContainerConfigError`                                       | 20s                                        | the secret may still be syncing                                                |
| unschedulable                                                      | 30s                                        | the autoscaler or a finishing pod may free room                                |
| `ImagePullBackOff`                                                 | 60s                                        | registries hiccup; `InvalidImageName` is at once                               |
| node stopped reporting (pod not ready, containers still say ready) | 60s                                        | a blip in the kubelet heartbeat                                                |
| terminating past its deadline                                      | 60s                                        | grace periods run long                                                         |
| running but not ready                                              | 2 minutes from start or from going unready | apps boot slowly; a startup probe owns slow starts                             |
| stuck creating                                                     | 5 minutes                                  | big images on a cold node                                                      |
| evicted                                                            | 2 in 10 minutes                            | one eviction is the node doing its job; the leftover pod is history and hidden |

One alert per kind, never per pod. The cause comes from the container itself: the exit code (127 command not found, 126 not executable, 137 with a liveness probe is the liveness check), the registry message (rate limit, login, missing tag), the missing secret's name, or the scheduler's shortage. A failing init container or sidecar is named, since it is not the user's app. A quota rejection (`ReplicaFailure`) is its own alert.

## Logs

Every log surface (the app console, the pod page, Observe, and the Raw logs view of a build) is the kit `LogViewer` with `toolbar`. Logs are evidence people copy into issues and chats, so the viewer is built for reading and taking, not for looking at.

- **Builds read like the tools people know.** The sheet is split 1 : φ into navigation and evidence. The left side sits on the sheet with no card: a hero gauge (`StatusDot` with `steps` and `orbit`), the status and "Step 3 of 5 · 14s", then a `StepRail` of the phases whose dots centre under the gauge and whose labels share its text column; clicking a phase jumps to it. The right side is the terminal (`BuildLog` + `BuildTerminal`, `deployment/build/`): a console surface grouped into collapsible phase sections like Vercel's (dot, phase, step count, duration; phases come from `buildSections` in `$lib/utils/build-sections.ts`, tested), with BuildKit steps in Docker's own notation (`=> 2/6 COPY …`, duration, CACHED or ERROR at the right) that unfold into their output. Building the image splits by Dockerfile stage (`groupStages`): Setup, then each `FROM … AS name` stage in the order it started with "4 of 5 cached · 12.3s", then Export. The card's edge is an overlay above its content, so sticky phase headers never cut it. The running or failed phase always has a section. Raw logs is the full `LogViewer` stream, where a step is a `source`. Add `?guides=1` to draw `GoldenReticle contained` over the sheet.
- **A failed build selects its step.** `diagnoseBuild` (`$lib/utils/build-failure.ts`, tested) names the step, the cause in plain words and the one thing to do. There is no separate failure card: the failed phase in the rail carries the cause as its detail, the failed section and step are open, and the cause and fix sit right under the error. A failure with no BuildKit step shows the fix at the end of its phase's section, without repeating error lines the log already shows. The same sentence feeds the "Build failed" alert. A build the user canceled is never called a failure, and a release that built but never became ready is a rollout failure with a link to the crash output. Unknown errors show the cleaned error, never a guessed cause.
- **Nothing you are reading disappears.** When a container restarts, the console keeps its earlier output above a "Restarted" line instead of swapping in the new container's empty log.
- **Cmd or Ctrl+A** inside a viewer selects its lines only.
- **Never taken away.** Nothing closes or swaps logs while someone may be reading. A finished build keeps its modal until it is closed. A pod that goes away keeps its logs on screen with "web-abc is gone · Show web-xyz". The console never jumps to a newer pod by itself.
- **One filter capsule:** the toolbar is a single capsule (search icon, active filters as removable chips, the query, "N lines" or "N of M") plus three quiet icons: wrap, copy, download. Level, time and source live in the capsule's filter popover, never as a row of dropdowns. Matches are highlighted with the CSS Custom Highlight API (no DOM rewriting). Cmd or Ctrl+F inside the viewer focuses it.
- **Filters:** level (all, warnings, errors), time (presets plus a from and to), source. Lines without a time inherit the one before them. "No lines match" offers Clear filters.
- **Take it:** one click copies exactly the lines shown as plain text (timestamps included, markup gone); Download saves them as `.log`. Selecting lines tints them in the accent and floats a capsule under the selection with the line count, Copy and Download, which copy whole lines. A selection survives live updates: following pauses while something is selected.
- **Find the failure:** errors and warnings are ticks along the right edge of the scroll area, placed by position in the stream; clicking one centres that line. A container in `CrashLoopBackOff` opens on its output from before the crash, because its current output is empty.
- **Stored logs:** where a log store answers (Observe Logs), the toolbar's search, level and time go to the server through `onFilters`, "Load earlier" pages by cursor, and `onExport` turns Download into a menu (what's shown, every matching line, NDJSON). A quiet `caption` says "Searching stored logs" or "Reading live from pods" so nobody mistakes a tail for history. The Observe range picker drives both Metrics and Logs. Search, level and pod live in the URL (`q`, `levels`, `pod`) next to the range (`range` or `from`/`to`), `at` and `panel`, so Copy link in the Observe toolbar always reopens exactly what is on screen.
- Line model: `LogLine` in `$lib/utils/log-lines.ts` (`text`, `ts`, `source`, `level`), built by `textLogLines` / `buildLogLines` and tested in `log-lines.test.ts`.

## Clickable rows keep their text

A `ListRow` with `onclick` takes the click on the row itself, so a drag that starts on its text selects it, and a click that ends a selection does not toggle the row. Keyboard users get the same action from the row's button.

## Hover-revealed actions

Actions that appear on hover (project + and →, the card's corner fan) show on `:hover` and on `:has(:focus-visible)`, never `:focus-within`, so a mouse click does not leave them stuck on screen. They stay open while their menu is open.

## Focus rings

Inside anything that scrolls or clips (sidebar, lists, panels), focus rings sit inside the element (`outline-offset: -2px`) so the scroll container never cuts them.

## Class names

Scoped classes must not reuse legacy global names (`btn`, `card`, `badge`, `input`,
`alert`, `dropdown`, `skeleton`, `page`) or Tailwind utility names (`group`, `grid`,
`ring`, `collapse`, `table`, `block`, `hidden`, `contents`, `container`, `border`,
`shadow`, `rounded`, `truncate`, `static`, `fixed`, `sticky`, `relative`, `isolate`).
Tailwind generates real CSS for any of those it sees in markup.

## Every action shows its result

A button never appears to do nothing. If what it changes lives on another tab or off screen, it
takes you there: "Logs" on a crash opens the output from before the kill
(`?tab=observe&view=killed`), on any other pod problem it switches to Overview with the console
on that pod. Selecting state the user can't see is not an action.

## Keys are ids

A keyed `{#each}` keys on an id, never on a display label (two projects can both have a `web`).
Helpers that group rows (by day, by month) merge into the existing group for a key instead of
starting a new one when rows arrive out of order; a repeated key throws `each_key_duplicate` and
takes the whole page down. Lists fed from several sources (`AlertStack`) drop duplicate ids.

## Kit class names

A kit root that other components select with `:global()` is namespaced `ui-*` (`ui-list`,
`ui-menu`, `ui-popover`). Never select a generic class like `.list` across components: a pattern
that happened to call its own root `.list` was pulled 12px up into a card title by
`SectionCard`'s list trim.

## Dark mode is for working at night

- Borders are quiet: `--border-default` is `neutral-2` and `--border-strong` `neutral-4` in dark
  (a step that reads as a hairline in light mode reads as a ring on a dark ground). High
  contrast mode keeps its stronger borders.
- No near-white surfaces in chrome. The active nav item is a dark `neutral-3` pill with the
  default text colour and the accent icon (`--nav-active-icon`).
- No gradient rims or shimmer. `--rim-glass` is a flat 7% white edge in dark.
- A solid fill behind a glyph or text uses `--status-<tone>-solid` with `--on-solid` (`ToneTile
solid`, toasts, `ModalIntro solid`). Status text tokens (`--status-<tone>`) are for text, dots
  and thin meters only; filling a tile with one gave pastel blocks and dark glyphs in dark mode.
  The guardrail counts these (`statusTextFills`).

## Problems live in one stack

Everything wrong on a page (health problems, apply errors, metric alerts, error spikes, rollbacks,
Observe findings) is a card in that page's `AlertStack`, never a banner of its own. Anything that
isn't critical is dismissible; a dismissal lasts the session and comes back when the condition
changes or recurs. Nothing else sits between the tabs and the content.

## Facts belong to what they describe

A fact (runtime, uptime, scanner, region) sits on the thing it qualifies: a `Disclosure` note, a
`Widget` meta, the header facts line. A loose caption under a toolbar or tab bar reads as
something left behind.

## Forms stack their labels

In a single-column form every field puts its label above a full-width control. Inline label and
control rows belong in `SettingsList` only; mixing the two breaks the column.

## Filter bars

A view that lists events (requests, logs) filters with one row above it: a capsule `Input` for
text, a capsule `SegmentedControl` for the one dimension everyone uses (status class), capsule
`Dropdown`s for the rest, a removable chip for a value picked from a row (click a client to filter
by it), and a ghost Clear that only appears while something is filtered. Filters are sent to the
server, and live rows arriving over SSE are checked against the same filters. An empty filtered
result says so and offers Clear.

## Charts: zero is a reading, missing is a gap

A value of 0 with traffic (a healthy 0% error rate) is drawn and listed; a value that is undefined
(error rate with no requests) is left out so the chart shows a gap. `MetricPanel` treats an all-zero
series as empty only for counts where zero means nothing happened; panels where zero is a reading
pass `zeroIsData`.

## The vine

`AsciiVine` is the only ornament in Orchard: a monospace vine drawn on a canvas at 14
frames a second that grows, sways and blooms. It is the brand mark in motion, so it is
rationed.

- One per screen, and only on arrival screens: sign-in, the updates sheet, a first
  empty project. Never on a screen people work in.
- It threads behind solid surfaces. Copy always sits on a surface, never on the vine.
- It grows once on arrival. `bloom` flowers it when the thing the person came for
  worked (signing in), and nowhere else.
- Its ink is `--accent-6` to `--accent-10`, so a brand colour recolours it. Never pass
  it a colour.
- It is decoration: below `full` motion it is drawn grown and still, and it stops
  drawing off screen and in hidden tabs.

On a brand field (the sign-in hero) its ink switches to cream and white and its glyphs to
Space Mono, matching the vine on orchard.my. `AuthShell` places it. Live reference at `/dev/ui#vine`; every sign-in state at
`/dev/ui/lab/sign-in`.

## Toasts

`toasts.add({ title, description?, color, action?, position? })` and
`toasts.promise(work, { loading, success, error })`. Titles are short and past tense
for results ("Changes saved"). The capsule is the raised theme surface (`--toast-fill` is
`--bg-raised`, `--toast-ink` the default text), so it is dark in a dark theme and follows
pinned colours; a hairline edge and shadow lift it off a page of the same tone. Titles are
never coloured, and status lives only in the glyph, a solid status fill with a white
(`--on-solid`) glyph. Position follows context: results of something the user
clicked go `bottom-right` (default); things that happened on their own (a build
finishing, connection lost) go `top-center`.

A toast's text column has the same inset on both sides of its content: 44px from the left (past
the glyph) and 20px from the right, never the 12px edge padding, or a full-width title or button
reads as jammed against the edge. Any width a component measures in script (the toast's open
width) reads the same constants its CSS uses, passed down as custom properties
(`--text-x`, `--text-end`); a number written twice drifts, and the wrap it causes looks like a
copy problem. Titles fit the open toast on one line: `Orchard was updated`, not a sentence.

## Truncation

Names and URLs truncate at the end. Middle truncation only for hashes, IDs and file
paths, where the end is what tells two values apart.

A single-line truncation is `overflow-x: clip; text-overflow: ellipsis; white-space: nowrap`,
never `overflow: hidden`. Labels trimmed with `text-box: trim-both cap alphabetic` have no room
below the baseline, so `overflow: hidden` cut the descenders off "g", "y" and "p" ("High" read
"Hiah"). Clipping only the inline axis keeps the ellipsis and lets descenders paint.

Rows of numbers next to bars (`TopList`) share one column sized to the widest value, so a list
of short numbers doesn't leave a wide empty gutter, and a hairline separates values from bars.

Anything a person or the cluster named (app, project, domain, image reference, branch, commit,
pod, email, path, client address) truncates or wraps on purpose; nothing grows its container.

- `overflow-x: clip` does not let a flex item shrink the way `overflow: hidden` does. A clipped
  flex item needs `min-width: 0`, and so does every flex ancestor up to the box that is sized.
- `text-overflow` does nothing on a flex container: put the ellipsis on a block child.
- An item in a wrapping flex row (`MetaList`, fact lines) also needs `max-width: 100%`, or a long
  value takes a line of its own and still overflows it.
- Truncated text carries `title` with the full value.
- Popovers never size to their content. `Menu`/`PopoverPanel` with `sameWidth` are exactly the
  trigger's width (12rem at least); every other menu caps at 20rem and its labels ellipsize.
- A count like `+2` is always a control that opens the full list, never decoration.
- Only reach for a character limit where CSS can't truncate (SVG text, native options, toast titles).

## Performance rules

- Never `background-attachment: fixed`, never `backdrop-filter` on scrolling content.
- Shadows never transition. Hover lift fades a pre-rendered shadow layer's opacity.
- Lists past ~50 rows rely on `content-visibility` (built into `ListRow`).
- Shaders run once per screen at most; lists use a baked still (`Aura` with `still`).

## Motion

One curve table, `CURVES` in `src/lib/design/springs.ts`. Each curve is a **response** (seconds, the
spring's period) and a **damping ratio** (1 = no overshoot, lower = more bounce), mirrored as CSS
tokens in `src/lib/design/springs.css` (`--spring-{name}`, `--spring-{name}-duration`,
`--fade-in/out/long`, `--curve-out/in`) by `pnpm gen:design`. Never write stiffness, damping, mass,
cubic-bezier or raw durations for interaction motion in a component. Name a curve. The motion
utilities and their pitfalls are in `AGENTS.md`.

| Name        | response | damping | Use for                                                                                    |
| ----------- | -------- | ------- | ------------------------------------------------------------------------------------------ |
| `snap`      | 0.22     | 0.88    | anything that opens or expands: folders, dropdowns, menus, popovers, panels                |
| `pop`       | 0.24     | 0.78    | things appearing: staggered rows, fan buttons, buds, badges                                |
| `settle`    | 0.17     | 1       | closing, exits, collapses (never bounces)                                                  |
| `glide`     | 0.28     | 0.92    | highlights, carets, scrubbers, sliding indicators, hover lift, height and position changes |
| `press`     | 0.12     | 1       | press feedback                                                                             |
| `morph`     | 0.3      | 0.8     | shape morphs: toast, notifier island, liquid button and menu                               |
| `bouncy`    | 0.32     | 0.6     | rare celebratory one-shots                                                                 |
| `cinematic` | 0.7      | 0.86    | full-viewport choreography seen once                                                       |

`smooth`, `snappy` and `interactive` are aliases for `glide`, `snap` and `press`.

**Tempo.** `TEMPO` in `springs.ts` (CSS `--tempo`) scales every curve's time at once without changing
its shape; `setTempo()` changes it at runtime (the Experiments panel has a slider). To make the whole
app snappier or calmer, change that one number. To retune one kind of motion everywhere, change its
row in `CURVES`.

**Using them.**

- CSS: `transition: transform var(--spring-snap-duration) var(--spring-snap)`; exits use
  `--spring-<name>-exit(-duration)`.
- Fades: `opacity var(--fade-in) var(--curve-out)`, `var(--fade-out) var(--curve-in)`,
  `var(--fade-long)`.
- WAAPI: `el.animate(frames, springTiming('snap', { distance, delay, exit }))` and
  `fade('in' | 'out' | 'long', delay)`.
- `motion` library: `transition('pop')` or `motion(el, kf, 'pop')`. Hand-rolled rAF springs:
  `physics(SPRINGS.glide)`.
- Distance: pass `distance` (px) and the curve is paced by `pace()`, √(distance / 420) clamped to
  0.55–1.6, so a small folder and a big one move at a similar speed.

### What moves, what doesn't

Motion when the **user caused a spatial change**: something opens, appears, leaves, reorders,
changes size, or gets pressed. Instant when **reality caused it** (the cluster, SSE, a refetch),
when it is a **text or value edit while typing**, for **focus**, and for anything repeated fast
enough that motion turns into latency. Every entrance has an exit. A removal animates out and its
space closes on a height spring; nothing vanishes and no gap jumps shut. In a swap the outgoing half
is instant on purpose: two panels sharing the layout is the jump this rule forbids, and the height
morph carries the continuity.

| Interaction                                                | Motion                                                                                      | Where it lives                                   |
| ---------------------------------------------------------- | ------------------------------------------------------------------------------------------- | ------------------------------------------------ |
| Menu, dropdown, popover, search picker, combobox           | `snap` in from the side it opened on, `snap` out toward it                                  | `overlayMotion` (Menu, PopoverPanel, Combobox)   |
| Modal                                                      | the shell fades on `settle` (no rise, no scale), content `swap`s in, backdrop fades with it | `Modal` (`motionPopover` with `curve: 'settle'`) |
| Sheet                                                      | `snap` in, `settle` out, backdrop fades with it                                             | `Sheet`                                          |
| Highlight inside an open menu or listbox                   | instant, it follows pointer and keys and a spring would trail them                          | `.ui-menu-item`, `.ui-dropdown-option`           |
| Selection moving (segmented control, tabs)                 | the indicator `glide`s to the new item, labels recolour                                     | `SegmentedControl`, `Tabs`, `UnderlineTabs`      |
| Content swap (tab panel, segmented content, source switch) | old content leaves at once, new rises in on `glide`, the container morphs height on `glide` | `Swap`                                           |
| Row the user adds (env var, port, volume, member)          | space opens on `glide`, content `pop`s in 50ms behind it                                    | `in:presence out:presence`, `ListRow presence`   |
| Row the user removes                                       | content fades on `settle`, space closes on `settle` 50ms behind it                          | same                                             |
| Disclosure, collapsible section                            | height on `glide`, chevron rotates on `snap`, collapsed body is inert                       | `Disclosure`                                     |
| Card or panel resizing after a user action                 | height `glide`                                                                              | `Swap`, `morphHeight`                            |
| Validation error                                           | text instant; its line opens and closes with `presence`; hint to error swaps in place       | `Field`                                          |
| Press on buttons, segments, steppers, checkboxes, cards    | `press` scale: 0.96 controls, 0.98 rows, 0.99 cards                                         | component CSS on `--spring-press`                |
| Press on popover triggers, disclosure summary, menu rows   | tint only. The popover measures its trigger, and menu rows close on release                 | `SelectTrigger`, `Disclosure`, menu CSS          |
| Switch, checkbox, radio                                    | thumb `glide`s, mark `pop`s                                                                 | `Switch`, `Checkbox`, `RadioGroup`               |
| Toast                                                      | `morph`                                                                                     | `Notifier`                                       |
| Status, build steps, pods, rows arriving from the cluster  | instant, with a `stateEcho` trail                                                           | `stateEcho`                                      |
| Typing: filtering a list, search results, live validation  | instant. Rows never stagger per keystroke and the panel resizes without a spring            | `SearchPicker`, `Combobox`, `CommandMenu`        |
| Focus ring                                                 | instant                                                                                     |                                                  |
| Repeated input (stepper clicks, arrow keys through tabs)   | the value is instant, only the indicator moves                                              |                                                  |
| Spinner in a trigger or button                             | instant swap with the chevron or label                                                      | `SelectTrigger`, `Button loading`                |
| Skeleton to content                                        | the skeleton fades in late so fast loads never show it; content replaces it instantly       | `Skeleton`                                       |
| First render of anything                                   | still. `presence` and `Swap` skip the first render; only arrival screens stagger in         |                                                  |

`presence` is opt-in on `ListRow`/`EntityRow` because the kit cannot tell a row the user added
from a row a refetch delivered. Pass `presence` where the person on this screen adds or deletes
the rows; leave it off for lists the cluster fills. A keyed `{#each}` needs a stable key (never
the index) or the wrong row leaves. `presence` handles a flex-column parent's `gap` itself (it
animates the edge margin from `-gap`), so a row leaving a `gap` stack does not leave a step behind.

## Theme engine (`src/lib/theme/`)

A theme is not a list of hex values. It is a constellation of colour nodes on a unit
square, and every token is generated from it.

```
ThemeSpec { angle, radius, count, blend, grain }  +  scheme (light|dark)
  -> specNodes()            1 to 3 nodes, derived
  -> deriveSimpleColors()   12 editable colours, background includes pageWash()
  -> [user overrides]       "Advanced colours" pins individual values
  -> generateThemeColors()  the ~47 engine tokens app.css expects
  -> generateScales()       --neutral-*, --accent-* and status scales
  -> generateChrome()       --theme-grain, --theme-accent-glow
```

**The field is polar.** Angle is hue, distance from the centre is saturation, the
conventional colour-wheel layout: grey at the centre, full chroma at the rim, with
`vividnessFor()` curving the ramp (`r ** 0.7`) so most of the disc reads as colour
rather than wash. Putting the saturation peak at the centre instead is what produces a
rainbow singularity there, since every hue converges on one pixel; a grey centre is the
same convergence but the colour they converge on is correct. `nodeSwatch()` and
`fieldFalloff()` share the ramp, so a node always reads as the colour it is sitting on.

**Why nodes only move together.** The spec stores one polar anchor, not a node list.
`specNodes()` spreads the rest evenly around the circle from it (`FANS`): a diameter for
two nodes, an equilateral triad for three. They always sit on opposite sides of the
canvas centre at the same radius, so the shape is symmetric by construction and the hue
relationship is a complement or a triad rather than anything editable. Dragging moves
the anchor; everything else follows.

Two things fall out of the polar form for free. The shape shrinks toward the centre,
because the chord between two points separated by a fixed angle is proportional to the
radius, so saturated themes cluster and washed-out ones spread. And there is no edge to
fall off: hue is cyclic, so the anchor can rotate forever without the constellation
appearing to clone itself across a boundary the way a clamped cartesian field does.

**Blend is scaled by the palette's own vividness.** `tint` and `surfaceShift` both
multiply by `vividness ** 0.6`, so a palette dragged to the rim of the field produces
grey surfaces however high blend is. Without that coupling the surface tint was the one
value in the engine that ignored the nodes entirely, and a constellation of visibly grey
dots still painted a saturated background.

**Blend moves lightness, not just chroma.** sRGB has almost no chroma available at the
top of the lightness range: at L 0.971 a red hue caps out around 0.014, so a blend that
only raised chroma was already clipped at half travel and the top half of the slider did
nothing. `surfaceShift` therefore walks every surface lightness toward the middle as
blend rises (light -0.062, dark +0.075), which is what actually buys the saturation.
`generateThemeColors` recovers that shift from the background's own lightness rather
than the ladder constant, so the rest of the surfaces follow even when the background
has been overridden by hand. `muted` tracks the shift at 0.6 weight so its contrast
against the background stays flat (4.41 to 4.42 across the whole light range) instead of
eroding as the page darkens.

**Why OKLCH.** `LADDERS` in `generate.ts` fixes perceptual lightness per scheme and lets
only hue and chroma come from the spec, so text-on-background contrast is a constant no
matter where the palette is dragged. The same ladder in HSL would wash yellows out and
muddy blues at identical values. `gamutMap()` walks chroma down rather than clipping
RGB, because clipping shifts hue and breaks the harmony the constellation is protecting.

**Chrome.** The blend wash is baked into the page colour, not painted over it.
`pageWash()` averages the nodes' chrome tints and `deriveSimpleColors` composites it
over the derived background at the strength the old overlay had (blend x `chromeAlpha` x
`chromeOpacity`, with a mesh counted at 0.6 coverage), so `--bg-app` is exactly the
colour the page shows. `body::before` carries only `--theme-grain`. Anything that fades
or blends into the page (`ProjectBackdrop`, `Page`'s footer, translucent bars) ends on
`--bg-app` and meets the body without a seam. The earlier overlay painted an accent wash
over the body that no token described, so every fade to `--bg-app` ended a few levels
darker than the page and left a hard edge. A pinned background is never washed.
`html.contrast-high` drops the grain.

**The wheel is a bare disc.** Drawing it inside a square plate leaves corner geometry
that means nothing, since every position outside the inscribed circle clamps back to
radius 1 and is unreachable. The count stepper sits under the disc rather than floating
inside it for the same reason.

**Classic themes** (`legacy.ts`) are the five hand-authored palettes the engine
replaced, kept as their original twelve hex values applied through the same override
channel the advanced editor uses. Their specs carry `blend: 0`, because those themes
predate the chrome layer and a gradient wash over them is exactly what stops them
looking like themselves. Touching any palette control drops the whole pinned set, since
a Classic theme is a snapshot rather than a starting point; individual pins made by hand
survive, because the store only clears overrides that match a Classic set outright.

The twelve pinned colours reproduce exactly. Tokens derived from them land within
0.04 OKLCH lightness of the originals, and `generateThemeColors` remaps the primary ramp
through the accent's real lightness rather than the ladder's so an overridden accent
keeps its ramp centred on itself. Skipping that remap put Electric's button fill 0.14 L
away from where it used to be.

**Fonts.** `fonts.ts` lists the six interface typefaces; the store writes the chosen
stack to `--font-sans`. Every non-default face carries a `size-adjust` in `app.css`
normalising it against Plus Jakarta Sans. OpenDyslexic also needs ascent and descent
overrides and a heavy size reduction because its advance widths are half again as wide
as the default.

**No flash.** `applyTheme` caches the generated custom-property text for both schemes in
`localStorage['orchard-theme-boot']`; the inline script in `app.html` injects it before
first paint and the store removes that style element once it owns the values.
