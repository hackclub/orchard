Networking decides who can reach an app and how. Each port gets a reach, from a public HTTPS URL to an address that only other apps in the same environment can use, so you expose exactly what you mean to. Behind every port, a Kubernetes Service balances traffic across the app's replicas. You manage ports on the app's **Network** tab.

## Reach

Reach sets who can connect to a port. You choose it when you create an app.

| Reach            | Result                                                                                   |
| ---------------- | ---------------------------------------------------------------------------------------- |
| **Private link** | An HTTPS URL behind Orchard sign-in. Only people with access to the project can open it. |
| **Public link**  | An HTTPS URL open to anyone.                                                             |
| **Public port**  | Raw TCP or UDP on an external address.                                                   |
| **Internal**     | A cluster-internal address with no URL.                                                  |

UDP ports support only **Public port** and **Internal**.

## Connect apps inside the cluster

To call another app in the same environment, use its internal address. **Network** > **Ports** shows the address below each port, in this form:

```text
<service>.<namespace>.svc.cluster.local:<port>
```

Inside the same namespace, the short form `<service>:<port>` also resolves.

Use the internal address for traffic between apps. A request to a public URL leaves the cluster, depends on public DNS, and passes through the ingress.

[Tenant namespaces deny incoming traffic by default](/operate/security/#network-isolation). Apps in the same namespace can reach each other. Each [environment](/start/concepts/#environment) has its own namespace, so apps in different environments cannot use internal addresses to reach each other.

3. In **Ports**, select **Add port**.

## Publish a TCP or UDP port

Publish a raw port to reach a game server or another non-HTTP service from outside the cluster.

### Prerequisites

- A layer 4 (L4) load balancer in the cluster.
- A public IP address. To set one for your organization, go to **Organization settings** > **Database defaults** > **Public database IP**. Otherwise, the organization inherits the instance default. If neither exists, publishing fails with an error. A superadmin sets the instance default as described in [Set a default public IP](/operate/finishing-setup/#set-a-default-public-ip).

This feature is not available in Cloudflare Tunnel mode, because tunnels carry HTTP only.

### Steps

<Tabs syncKey="dashPlusCli">
<TabItem label="Dashboard">

1. Open the app.
2. Go to **Network**.
3. In **Ports**, turn on **Public** for the port.
4. Select **Make public**.

The public address replaces the internal address on the row. Until the load balancer assigns the address, the row shows **Waiting for an address**. If the load balancer reports an error, the row shows the reason instead. For the causes, refer to [Troubleshoot a public address](#troubleshoot-a-public-address).

</TabItem>
<TabItem label="CLI">

```sh
orchard service port public enable <service-id> <port-id> --deployment <id>
```

</TabItem>
</Tabs>

:::caution
Public TCP and UDP traffic skips the HTTP layer, so [app protection](/deploy/protection/) does not apply. The service must handle its own authentication.
:::

### Keep client addresses

By default, a public port uses `externalTrafficPolicy: Cluster`. Any node accepts the connection and forwards it with source NAT, so the app sees a node address instead of the visitor's. Turn on **Keep client addresses** when the app needs the real address, for example a mail server that checks SPF and blocklists, or an app that rate-limits per IP. Orchard then sets `externalTrafficPolicy: Local`.

With the setting on, only nodes that run a replica of the app accept traffic on the port. On a single node, or with a load balancer that announces from those nodes only (k3s ServiceLB, MetalLB in L2 mode, Cilium L2 announcements or BGP), this needs no other change. A load balancer that sends traffic to every node drops the connections that reach a node without a replica.

<Tabs syncKey="dashPlusCli">
<TabItem label="Dashboard">

Select **Keep client addresses** in the **Make public** dialog. For a port that is already public, open the port's menu and select **Keep client addresses** or **Stop keeping client addresses**. A port with the setting on shows a **Client IP** badge.

</TabItem>
<TabItem label="CLI">

```sh
orchard service port public enable <service-id> <port-id> --deployment <id> --preserve-client-ip
```

Run the same command with `--preserve-client-ip=false` to turn it off. The port keeps its public port number either way.

</TabItem>
</Tabs>

### Troubleshoot a public address

A public port or a [public database](/data/databases/#public-access) is reachable only after the cluster's load balancer assigns it an address. Orchard reads the state from Kubernetes and shows one of these states:

| State                      | Meaning                                                                                    |
| -------------------------- | ------------------------------------------------------------------------------------------ |
| **Live**                   | The load balancer assigned the address. The port accepts connections.                      |
| **Waiting for an address** | The load balancer has not assigned an address yet. A cloud load balancer can take minutes. |
| An error with a reason     | The load balancer reported a problem. The address does not accept connections.             |

If Orchard cannot read the state from Kubernetes, the row shows the address without **Live**.

| Reason                                                                | Cause and fix                                                                                                                                                                                                                                    |
| --------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Port _N_ is already in use on the server**                          | On k3s, the built-in load balancer (ServiceLB) listens on the port on every node, and another LoadBalancer Service or a pod with a host port already holds that port. Turn **Public** off and on to get a new port, or remove the other Service. |
| **No address could be allocated** or **No address could be assigned** | MetalLB or Cilium has no free address in its pool, or the public IP is not in a pool. Add the organization's public IP to an address pool, or free an address.                                                                                   |
| **The load balancer could not be created**                            | The cloud provider rejected the request. The reason includes the provider's message, for example a quota limit. Fix the cause in the cloud account. Orchard picks up the address when the provider assigns it.                                   |
| **The load balancer assigned _X_ instead of _Y_**                     | The load balancer ignores the requested IP address. Set the organization's public IP to the assigned address, or configure the load balancer to honor `spec.loadBalancerIP`.                                                                     |
| **No load balancer assigned an address after 5 minutes**              | Nothing in the cluster handles LoadBalancer Services. Install a load balancer such as MetalLB, or use k3s with ServiceLB.                                                                                                                        |

To read the full history, run `kubectl describe service <name> -n <namespace>` and check **Events**.

## Outbound traffic

Apps can reach the public internet. The tenant network policy blocks traffic to private address ranges and to the link-local range that holds cloud metadata services. It also blocks the Kubernetes API, the control-plane database, and unpublished services in other namespaces.

## Request headers

Traffic reaches your app through at least one proxy, so the socket peer is the proxy. Client details arrive in headers.

| Header              | Set by                             | Contains                                |
| ------------------- | ---------------------------------- | --------------------------------------- |
| `X-Real-IP`         | The ingress                        | The peer of the inbound TCP connection  |
| `X-Forwarded-For`   | The ingress, appended for each hop | The client chain, left to right         |
| `X-Forwarded-Proto` | The ingress                        | `https` or `http`, as the client saw it |
| `X-Forwarded-Host`  | The proxy                          | The hostname the client requested       |

To get the client address, use `X-Real-IP`. The ingress sets it to the actual peer and overwrites any value from the client.

Clients can add entries to `X-Forwarded-For`. Trust only the entries your own proxies added. If your framework derives the client IP from this header, configure the number of proxy hops to trust.

A domain with [protection](/deploy/protection/) adds a hop. The protection proxy forwards these headers and appends the peer it saw. It removes `x-orchard-protection-bypass` before the request reaches your app.

To build absolute URLs, use `X-Forwarded-Proto` and `X-Forwarded-Host`. Otherwise, a framework can generate links that point at a pod IP address.
